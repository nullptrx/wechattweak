# 微信 4.1.13（269628）ARM64 适配

## 行为

- 自己发送的消息：撤回继续使用微信原生流程，包括原生撤回提示。
- 他人发送的消息：保留原消息，另行插入微信生成的撤回提示。
- 原消息未找到时：保留原生处理。不能根据不存在的消息判断发送者。
- 此版本仅适配 ARM64 防撤回；旧版本配置保持原样。

## 样本与地址

样本来自本机 `/Applications/WeChat.app`，CFBundleVersion 为 `269628`，
CFBundleShortVersionString 为 `4.1.13`。原始应用签名为 Tencent Mobile
International Limited，Team ID `5A4RE8SF68`，启用 Hardened Runtime。

分析对象是 `Contents/Resources/wechat.dylib` 的 ARM64 slice，SHA-256：

```text
c4cc52d856929ce294dfcf63461f81ac646353ff0987a43ad5f4ebbfe9262e42
```

以下均为未加 ASLR slide 的虚拟地址，不能直接用作 universal 文件偏移。

| 地址 | 静态分析依据 |
| --- | --- |
| `0x49af9a0` | XML 解析后保存撤回消息 ID，旧版的无条件清零策略会丢失发送者判断所需的信息，因此新版不修改此处 |
| `0x32414c8` | 按会话和消息 ID 查找原消息，结果为 `sp+0x38` 的可选 Message，存在标志在 `sp+0x2b0` |
| `0x494d540` | 微信原生发送者判断：比较 Message 的 `+0x18` 用户名与当前账号用户名；返回值非零表示自己发送 |
| `0x324209c` | 原消息不存在时跳过存在分支；恢复查询路径也会通过 `0x32426bc` 到达存在分支 |
| `0x32420a0` | 两条查询成功路径共同进入的原消息处理位置，原指令为 `ldr w8, [sp, #0x14c]` |
| `0x3242b64` | 原生新提示插入路径：从撤回事件读取会话，用事件元数据填充提示，然后调用 `0x2eeeb68` 插入 |
| `0x3242cfc` | 原生原消息处理调用，接收 `sp+0x38`；他人撤回的补丁分支跳过此路径 |
| `0x5b23180` | `__TEXT,__text` 内的零填充区，前一个函数在 `0x5b23174` 返回，后续代码从 `0x5b24000` 开始 |

新提示对象位于 `sp+0x628`，其消息 ID 位于 `sp+0x720`。
仅对他人撤回将**新提示**的 ID 清零，再进入新提示插入路径，避免替换原消息。
原消息对象和存在标志不变，原生清理代码仍会正常析构该对象。

## 补丁

先写入 32 字节条件代码，再将 `0x32420a0` 改为跳转到条件代码。
两处都提供 `expected` 字节校验；重复执行由 Patcher 的幂等检查处理。

```asm
; 0x5b23180
add  x0, sp, #0x38
bl   0x494d540                 ; 原消息是否由自己发送
cbnz w0, own
str  xzr, [sp, #0x720]         ; 仅清零新提示的 ID
ldr  x22, [sp, #0x2f0]         ; 撤回事件对象
b    0x3242b64                 ; 插入新提示，保留原消息
own:
ldr  w8, [sp, #0x14c]          ; 重放被替换的原指令
b    0x32420a4                 ; 原生流程
```

发送者判断使用微信自身的函数，不匹配“你撤回了”等本地化文案。

## 验证

已完成：

- Swift release 构建。
- 在原始 universal dylib 的临时副本上，通过项目 Config/Patcher 实际写入补丁并重复执行，验证幂等性。
- 完整字节比较：只有配置指定的 ARM64 字节发生变化，x86_64 slice 不变。
- Unicorn 执行配置中的真实 ARM64 指令及样本内的原生发送者判断函数。仅模拟账号服务和 `memcmp`；覆盖短/长用户名、自己/他人/空发送者、单聊/群聊字段，共 16 种组合，检查分支、消息 ID、栈和必要寄存器。

复现指令级验证（需要 Python 和 `unicorn`）：

```bash
python3 scripts/verify_revoke_269628.py /Applications/WeChat.app/Contents/Resources/wechat.dylib
```

验证脚本要求未打补丁的原始样本。部分 macOS 沙箱不允许模拟器执行 JIT，需要在普通终端运行。

已使用本地配置安装到微信 269628，安装后的补丁字节和完整应用签名验证通过，
用户实际试用后确认可用。具体测试场景未逐项记录，尚不能视为完整的端到端覆盖。
