# 微信 4.1.13（269629）ARM64 禁止更新适配

## 行为

此版本禁用 `XAppUpdateManager` 的更新启动、后台检查、手动检查和自动更新入口，
同时让“自动下载更新”和“允许检查更新”始终返回 `false`。

本配置仅包含禁止更新补丁，不包含防撤回或多开补丁。

## 样本

分析对象为 `/Applications/WeChat.app/Contents/Resources/wechat.dylib` 的 ARM64
slice。原始 universal dylib 的 SHA-256：

```text
67ad41d6c7b59b497c74e3f93095e5762a4312707a3462baaeaffe5347c4ea8e
```

以下地址由 `XAppUpdateManager` 的 Objective-C 相对方法列表解析得到，均为未加
ASLR slide 的虚拟地址：

| 方法 | 地址 | 原始行为 |
| --- | ---: | --- |
| `startUpdater` | `0x27becc` | 初始化并启动 Sparkle 更新器 |
| `checkForUpdates:` | `0x27e0f8` | 发起更新检查 |
| `startBackgroundUpdatesCheck:` | `0x27e3c8` | 启动后台更新检查 |
| `enableAutoUpdate:` | `0x27e7e8` | 修改自动更新状态 |
| `automaticallyDownloadsUpdates` | `0x289060` | 返回自动下载状态 |
| `canCheckForUpdate` | `0x289070` | 返回是否允许检查更新 |

每个方法入口均替换为：

```asm
mov w0, #0
ret
```

配置同时记录原始 8 字节作为写入保护。样本或版本不匹配时，Patcher 会拒绝修改。

## 验证

静态验证会重新解析 Objective-C 元数据，而不是只核对硬编码地址：

```bash
python3 scripts/verify_update_269629.py /Applications/WeChat.app/Contents/Resources/wechat.dylib
```

安装前应在未修改的应用副本上执行一次完整 Patch，检查只有上述六处 ARM64 字节
发生变化、x86_64 slice 不变，并验证补丁后的应用签名。
